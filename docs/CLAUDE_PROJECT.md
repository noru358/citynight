## 프로젝트 지침 (붙여 넣을 글)

이 프로젝트는 게임 citynight 작업 공간이다. 기지는 GitHub noru358/citynight 저장소다. 대화를 시작하면 저장소를 붙이고 HANDOFF.md → docs/DIRECTION.md → docs/TEAMS.md 순서로 읽는다. 세션을 끝낼 때 HANDOFF.md의 현재 상태·다음 할 일과 docs/DIRECTION.md 결정 기록을 갱신하고 푸시한다.
사용자는 한국어로, 돌려 말하지 않는 직설적인 분석을 원한다. 표·굵은 글씨·번호 틀이 많은 답은 AI 티가 나고 읽기 어렵다고 싫어한다. 짧은 답에 되묻지 말고 의도를 추론한다.
이야기는 사용자에게서 출발한다. 줄거리·설정 후보를 여러 개 뽑아 내밀지 않는다. 캡션·대사는 사용자가 정하기 전까지 자리표시로 둔다.
docs/DIRECTION.md의 거부 목록은 다시 제안하지 않는다.
사용자는 F키를 못 쓴다. 디버그는 화면 버튼과 Tab. 주 작업은 맥북, 직장에서는 윈도우(설치 없는 묶음: Play.cmd).

## 새 프로젝트 첫 안건

이전 대화 마지막 질문: 스토리팀(사건 종류 정하기)과 아트팀(기준 해상도·주인공 키·팔레트 정하기) 중 어디부터 할지.

Claude 판단: 둘 다 막혀 있지만 성격이 다르다. 아트 기준은 기술 결정이라 Claude가 안을 내고 사용자가 고르면 하루 안에 끝나고, 늦게 정할수록 맵·카메라·이동 수치를 다시 맞춰야 해서 비용이 커진다. 스토리의 사건 종류는 사용자 머리에서 나와야 하고 시간이 걸린다. 그래서 순서는 아트 기준을 먼저 짧게 확정하고, 바로 스토리로 간다.

아트 기준에서 정할 것(안은 새 대화에서 Claude가 그림 시안과 함께 낸다):
- 기준 해상도: 640×360(16px 타일, 정수 배율 2·3배로 1280×720·1920×1080) 같은 후보 중 하나.
- 주인공 키: 기준 해상도에서 몇 픽셀인가(예: 24~32px). 이게 정해지면 이동 수치를 같은 비율로 환산해야 한다(지금 수치는 32px 타일 기준).
- 팔레트 한 장: 밤 하늘·건물·창 불빛·네온 포인트. 시티팝 앨범 아트 느낌.
